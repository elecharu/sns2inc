# Code & UI Optimization Rule

모든 소스 코드 작성 및 리팩터링 시 코드 가독성, 유지보수성, 직관성을 극대화하기 위해 다음 원칙을 준수합니다.

### 1. 직관적인 네이밍 및 구현
- 모든 작업을 수행할 경우 가장 직관적으로 코드 및 변수, 함수명을 이해할 수 있는 방향으로 진행하며, 현재 프로젝트 안에 이미 구현된 변수/함수 네이밍 컨벤션을 준수하여 일관성 있게 작성합니다.
- 성능적인 측면을 고려하여 가장 직관적이며 가시성이 좋은 코드를 기준으로 작성합니다.

### 2. 주석 작성 표준
- 주석을 작성할 때는 단순 기능 나열에 그치지 않고, "YYYY-MM-DD 기능설명" 형식을 준수하되 **어느 부분(화면/모달의 어떤 UI 영역, 패널, 컨트롤, 그리드 등)에 해당하는 기능인지와 구체적으로 어떤 역할을 수행하는지**를 직관적이고 명확하게 명시합니다.
  (예: `// YYYY-MM-DD 전체 행 검사 후 모달 상단 패널 콤보박스 합부판정 체크`, `// YYYY-MM-DD 하단 그리드 개별 행 합부판정 및 행 배경색 갱신`)

### 3. 화면 스크립트 작성 제약사항
- **스크립트 버전(`srcVersion`) 임의 변경 금지**:
  - 화면 소스(`.aspx` 등)에서 자바스크립트를 로드할 때 브라우저 캐시 문제를 해결하기 위한 목적으로 `srcVersion` 호출부(`?ver=<%= BasePage.srcVersion %>`)에 임의의 버전 번호, 날짜, 타임스탬프를 덧붙이거나 임의로 수정하는 작업을 절대 수행하지 않습니다.
- **과도한 장식용 구분선/배너 주석 작성 금지**:
  - 자바스크립트 등 일반 소스 파일에서 `/******/`, `//////`, `=====`, `-----` 등 특수문자를 수십 개씩 길게 나열하여 만든 과도한 장식용 구분선이나 배너 형태의 주석은 코드 가독성을 저해하므로 절대 작성하지 않습니다.
  - 영역 구분이 필요할 경우 불필요한 특수문자 반복 없이 `/* 일상점검 (EQM01) 영역 이벤트 */`와 같이 간결하고 직관적인 단일 행 주석 형식으로만 작성합니다.
- **파일 최상단 임의의 헤더 주석(프로그램 ID/메뉴 경로 등) 작성 금지**:
  - 소스 파일 최상단에 `/* EQM1001_R03: 설비관리 - 설비점검 - 설비점검계획 */`과 같은 임의의 프로그램 ID나 메뉴 경로 형태의 헤더 주석을 작성하지 않습니다.
  - 자바스크립트 파일의 최상단은 `/// <reference path="../../Script/reference.js" />` 또는 실제 실행 코드로 시작하도록 작성합니다.

### 4. 기존 소스코드 존중 및 최소 변경 원칙 (기존 코드 최대한 재활용)
- **기존 소스코드 최대 재활용**:
  - 기존에 이미 작성되어 동작하고 있는 소스코드 구조, 구현 스타일, 변수명 및 처리 흐름을 최대한 그대로 존중하고 재활용합니다.
- **불필요한 임의 재작성/과도한 리팩터링 금지**:
  - 기능상 명백한 결함이나 버그가 발생하는 경우가 아니라면, 개발자의 개인 취향이나 불필요한 고도화 목적으로 기존 소스코드를 임의로 갈아엎거나 재작성하지 않습니다.
  - 문제 해결을 위해 수정이 필요한 경우에도 기존 로직의 형태를 최대한 보존하면서 필요한 최소한의 코드만 간결하고 직관적으로 수정합니다.
