# 소스 코드 주석 간소화 및 .aspx/.aspx.cs 주석 금지 규칙

화면 UI 마크업 및 비하인드 코드의 가독성을 보장하고, 소스코드 내 불필요한 날짜 및 다중 행 주석 누적을 방지하기 위해 다음 원칙을 절대적으로 준수합니다.

---

### 1. `.aspx` 및 `.aspx.cs` 주석 추가 절대 금지

- **배경**:
  - 화면 마크업(`.aspx`) 및 C# 비하인드 코드(`.aspx.cs`)에 날짜별 변경 이력 주석(`<%-- YYYY-MM-DD ... --%>`, `// YYYY-MM-DD ...`)이 누적되면, 태그 구조와 레이아웃 흐름을 파악하기 매우 어려워지고 코드가 지저분해집니다.
- **원칙**:
  - **`.aspx` 화면 마크업 파일 및 `.aspx.cs` 비하인드 소스에는 어떠한 주석(날짜 주석, 기능 설명 주석 등)도 일체 추가하지 않습니다.**
  - 기본 레이아웃 템플릿의 섹션 주석(`<%-- PAGE --%>`, `<%-- HEAD --%>`, `<%-- BODY --%>`, `<%-- POP --%>` 등)을 제외한 모든 인위적인 신규/변경 주석 작성을 엄격히 금지합니다.
  - 마크업이나 비하인드 코드 수정 시에도 주석을 남기지 않고 순수 태그 및 로직만 간결하고 깔끔하게 작성합니다.

### 1-1. `<asp:Content>` 외부 텍스트 및 중복 BOM 유입 절대 금지 (줄 1 파서 크래시 방지)

- **배경 및 원인 (파서 치명 오류 실사례)**:
  - 마스터 페이지(`MasterPageFile`)를 상속하는 `.aspx` 콘텐츠 페이지는 `<%@ Page ... %>` 선언부와 `<asp:Content ...>` 태그 바깥에 어떠한 텍스트, 공백, 보이지 않는 문자도 허용하지 않습니다.
  - 태그 바깥에 텍스트가 들어가거나, 파일 저장 시 **이중 BOM(`0xEF 0xBB 0xBF 0xEF 0xBB 0xBF`)**이 기록되면 두 번째 BOM이 본문의 보이지 않는 문자(`\uFEFF`, Zero Width No-Break Space)로 취급되어 ASP.NET 엔진이 `"Content 컨트롤이 포함된 콘텐츠 페이지에는 Content 컨트롤만 사용할 수 있습니다. 줄 1:"` 오류를 발생시키며 페이지 전체 로딩이 중단됩니다.
- **방지 원칙**:
  - `<asp:Content>` 컨트롤 바깥 영역에는 섹션 주석 외에 어떠한 임의의 문자열도 작성하지 않습니다.
  - `.aspx` 파일 저장 시 반드시 `encoding.md` 규칙에 따라 **정확히 단 1개의 UTF-8 BOM (`\xef\xbb\xbf`)**만 유지되도록 3바이트 무결성을 철저히 검증합니다.

### 2. 소스 코드(.js, .cs) 주석 작성 표준 (날짜 제거 및 단일 행 간소화 원칙)

- **날짜 주석(`// YYYY-MM-DD`) 전면 배제 (날짜 포기)**:
  - 클라이언트 스크립트(`.js`) 및 C# 소스 파일(`.cs`) 내부에는 작업 일자(`// YYYY-MM-DD ...`)를 절대 기재하지 않습니다.
  - 날짜별 작업 이력 및 세부 변경 배경은 소스코드가 아닌 `WORK_HISTORY.md` 및 Git 커밋 메시지에서 추적·관리합니다.
- **두 줄 이상의 다중 행 설명 주석 절대 금지**:
  - 날짜별로 두 줄 이상 주석을 쌓거나, 버그 발생 배경·단말기 특성·구현 히스토리를 여러 줄에 걸쳐 나열하는 행위를 엄격히 금지합니다.
- **최대한 간략한 단일 행(1줄) 기능 설명 원칙**:
  - 함수나 주요 로직 상단에는 오직 **"해당 코드가 무엇을 하는지"**만 나타내는 간결한 단일 행 주석(`// [기능 또는 처리 내용]`)만 1줄로 작성합니다.
  - **비교 예시**:

    ```javascript
    // [올바른 예: 간결한 1줄 기능 설명]
    // 점검값 입력 팝업 오픈 (OK/NG 및 숫자패드 분기)
    function OPEN_ITEM_INPUT(gridId, rowIndex, field) { ... }

    // [금지 예: 날짜 포함 및 2줄 이상 나열]
    // 2026-11-09 점검값 입력: 점검값구분 03(OK/NG)은 OK·NG 버튼, 그 외는 숫자패드
    // 2026-11-10 점검값 칸에서만 열림 (한 번 누르기로 바꾸면서 다른 칸을 눌러도 열리지 않게 함)
    function OPEN_ITEM_INPUT(gridId, rowIndex, field) { ... }
    ```

### 3. 파일 종류별 주석 규칙 요약

| 파일 종류 | 주석 작성 규칙 | 세부 기준 |
| :--- | :--- | :--- |
| **`.js` (JavaScript)** | **날짜 없는 간결한 1줄 기능 주석** | 날짜 기재 금지, 두 줄 이상 다중 행 설명 금지, 함수/로직 상단에 "무엇을 하는지"만 1줄 요약 작성 |
| **주요 기능 `.cs` (리포트 등, `.aspx.cs` 제외)** | **날짜 없는 간결한 1줄 기능 주석** | 날짜 기재 금지, 두 줄 이상 다중 행 설명 금지, 메서드/로직 상단에 "무엇을 하는지"만 1줄 요약 작성 |
| **`.aspx` (화면 마크업)** | **주석 추가 일체 금지** | 날짜 주석 및 기능 설명 주석 작성 금지, `<asp:Content>` 외부 텍스트 및 중복 BOM 절대 금지 |
| **`.aspx.cs` (비하인드)** | **주석 추가 일체 금지** | 날짜 주석 및 기능 설명 주석 작성 금지 (순수 C# 코드 유지) |
| **`.sql` (프로시저)** | **최상단 1일 1행 작성** | 최상단 `Modify:` 영역에만 일자당 1행 작성, 내부 쿼리 라인 날짜 금지 (`procedure_history.md` 준수) |
