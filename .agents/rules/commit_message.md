# Git Commit Message Convention Rule (한국어 커밋 메시지 규칙)

Git 커밋 메시지를 생성하거나 작성할 때 가독성과 일관성을 위해 다음 원칙을 반드시 준수합니다.

### 1. 커밋 메시지 한국어(Korean) 작성 강제
- 커밋 메시지의 요약 설명은 **반드시 한국어(한글)**로 작성해야 합니다. 영문으로 작성하지 마십시오.
- 형식은 **Conventional Commits** 표준을 엄격히 준수합니다:
  ```
  <type>: <한글 요약 설명>
  ```
- 따옴표(따옴표, 쌍따옴표)로 감싸지 말고, 1문장으로 간결하게 핵심 변경 사항을 명사형 종결로 작성합니다.

### 2. 커밋 타입(Type) 접두사 및 작성 예시
- `feat`: 신규 기능 추가
  - 예시: `feat: REV 버전관리 기능 추가`
  - 예시: `feat: 점검계획 승인상태 필터 추가`
- `fix`: 버그 및 오류 수정
  - 예시: `fix: 정기점검 점검값 유효성 검증 오류 수정`
  - 예시: `fix: 동일 월 정기점검 중복 등록 방지`
- `refactor`: 코드 리팩터링 및 구조 개선
  - 예시: `refactor: 정기점검 주기관리 쿼리 및 프로시저 최적화`
  - 예시: `refactor: 화면 입력값 검증 로직 프로시저로 이동`
- `style`: 코드 스타일, 주석 정리, 마크업 구조 정돈
  - 예시: `style: aspx 화면 마크업 날짜 주석 제거 및 순수 태그 정리`
  - 예시: `style: 프로시저 최상단 Modify 이력 1일 1행 정리`
- `perf`: 성능 개선 및 속도 향상
  - 예시: `perf: 설비 점검실적 연도별 사전집계 튜닝으로 조회 속도 개선`
- `docs`: 문서 및 작업 이력 갱신
  - 예시: `docs: 작업 이력 및 프로젝트 규칙 문서 갱신`

### 3. 금지 사항
- **영문 커밋 메시지 작성 절대 금지**:
  - `feat: add approval status filter` (X) ➔ `feat: 점검계획 승인상태 필터 추가` (O)
  - `refactor: optimize routine inspection queries` (X) ➔ `refactor: 정기점검 쿼리 최적화` (O)
  - `fix: memory leak in server` (X) ➔ `fix: 서버 메모리 누수 오류 수정` (O)
- 인위적인 긴 설명이나 불필요한 마침표 지양.
