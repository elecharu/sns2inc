# File Encoding & Line Endings Rule

모든 소스 코드 및 문서 파일을 생성하거나 수정할 때 파일 손상, 한글 깨짐, 불필요한 줄바꿈 중복을 방지하기 위해 다음 원칙을 반드시 준수합니다.

### 1. UTF-8 with BOM 인코딩 강제
- **적용 대상**: 모든 소스 코드 및 텍스트 파일 (`.cs`, `.xaml`, `.aspx`, `.js`, `.sql`, `.css`, `.html`, `.md` 등)
- **인코딩 표준**: 반드시 **UTF-8 with BOM** (파일 시작 바이트: `\xef\xbb\xbf`) 방식으로 저장합니다.
- **목적**: Visual Studio, IIS, MSBuild, Windows OS 환경에서 한글 주석이나 문자열이 깨지지 않고 정상 인식되도록 보장합니다.

### 2. 표준 Windows CRLF 개행 통일
- **줄바꿈 표준**: 모든 줄바꿈 문자는 Windows 표준인 **CRLF (`\r\n`)**로 정상화합니다.
- **주의사항**:
  - `\r\r\n`과 같이 잘못된 중복 캐리지 리턴이 발생하면 에디터 상에서 줄마다 빈 줄이 한 줄씩 추가되어 파일 라인이 2배로 불어나므로 이를 철저히 방지합니다.
  - Unix 방식의 단독 `LF (\n)`나 레거시 `CR (\r)`이 섞이지 않도록 저장 전 항상 통일합니다.

### 3. 파일 저장 후 무결성 검증
- 파일 수정 후 바이너리 레벨에서 아래 2가지를 스스로 즉시 확인합니다:
  1. 첫 3바이트가 `\xef\xbb\xbf` (UTF-8 BOM)인지 확인
  2. 파일 내용 중에 `\r\r\n` 문자열이 없는지 확인
