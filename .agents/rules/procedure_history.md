# Stored Procedure History Comment Rule (1일 1행 원칙)

데이터베이스 저장 프로시저(`.sql`) 최상단 이력 주석(Comment / Modify) 작성 시 가독성 및 이력 추적성을 극대화하기 위해 다음 원칙을 준수합니다.

### 1. 1일 1행 통합 기록 원칙 (하루 한 줄 작성)
- **배경**: 동일 일자에 여러 차례 수정 및 기능 개선이 이루어질 때마다 행을 나누어 추가하면 이력 블록이 지나치게 길어져 소스 가독성을 저해합니다.
- **원칙**:
  - **하루에 발생한 모든 수정/개선 내역은 날짜별로 반드시 단 한 줄(1행)로 간결하게 통합하여 작성**합니다.
  - 동일한 날짜(`YYYY-MM-DD`)가 중복으로 여러 행에 걸쳐 나열되지 않도록 합니다.
  - 하루 동안 작업한 여러 기능이나 변경사항은 쉼표(`,`) 또는 가운뎃점(`·`)을 활용하여 핵심 키워드 위주로 압축 요약합니다.

### 2. 간결하고 직관적인 한 줄 요약 표준
- **장황한 문장 나열 지양**:
  - 화면 UI 상세 설명이나 장황한 수식어를 배제하고, 해당 일자에 변경된 DB 핵심 로직(검증, 집계, 조회 조건, 신규 분기 등)을 직관적인 명사형 또는 간결한 어미로 요약합니다.
- **비교 예시**:
  ```sql
  -- [지양] 동일 일자에 여러 줄로 나열된 장황한 이력
  -- 			2026-10-02 					한성수	주기관리 월별 점검자를 사원코드로 저장·조회 (월 칸은 사원명 표시, MxxCD는 저장값, 기존 사원명 저장값은 그대로 표시)
  -- 			2026-10-02 					한성수	조회 성능 개선 (주기관리 조회 정기점검 설비 사전집계, 미등록 항목 조회 교차조인 제거, 설비별 복사 일괄 등록)
  -- 			2026-10-02 					한성수	주기관리 저장·삭제 시 정기점검 실적이 있는 월은 점검자 변경·삭제 불가
  -- 			2026-10-02 					한성수	주기관리 조회 대상을 정기점검 등록과 같게 변경 (설비의 최신 승인 리비전에 정기점검 항목이 있는 설비)
  -- 			2026-10-02 					한성수	설비별 정기점검 복사 시 대상·원본 설비 지정 확인 (화면 확인을 프로시저로 이동)

  -- [권장] 1일 1행으로 간결하게 통합된 이력
  -- 			2026-10-02 					한성수	주기관리 점검자 사원코드화·실적 월 잠금·승인본 대상 통일, 복사 검증 및 성능 개선
  ```

### 3. 정렬 및 포맷 표준
- 프로시저 최상단 주석 블록 내에서 일관된 들여쓰기와 열 정렬을 유지합니다:
  ```sql
  -- *****************************************************************************
  -- Comment: [프로시저 설명]
  -- Create: 	YYYY-MM-DD  	생성 			[작성자]
  -- Modify: 	YYYY-MM-DD 		마이그레이션	[작성자]
  -- 			YYYY-MM-DD 					[작성자]	[1일 1행 통합 작업내용]
  -- *****************************************************************************
  ```

### 4. 프로시저 내부 쿼리 라인 날짜 기재 금지 (`procedure.md` 준수)
- 작업 일자(`YYYY-MM-DD`) 및 작업자 정보는 **오직 최상단의 `Modify` 이력 영역에만 기재**합니다.
- 프로시저 내부 분기(`WHEN ... THEN`)나 개별 쿼리 라인에는 날짜 주석을 절대 표기하지 않고, 간결한 기능 명칭만 작성합니다.
