# Project Context Rule (프로젝트 경로 및 DB 스키마 유동 적용 규칙)

본 `.agents` 규칙 세트는 여러 MES 프로젝트에 공통으로 복사하여 사용합니다. 프로젝트마다 루트 경로, 폴더 구성, DB 스키마명이 다르므로 규칙 문서와 소스에 특정 프로젝트 값을 하드코딩하지 않고, 작업 시점에 현재 프로젝트 기준으로 판별하여 적용합니다.

---

### 1. 규칙 문서 내 치환 표기
| 표기 | 의미 | 판별 방법 |
| :--- | :--- | :--- |
| `{PROJECT_ROOT}` | 현재 작업 중인 프로젝트 루트 | `.agents` 폴더가 위치한 디렉터리 |
| `{SCHEMA}` | 프로시저가 속한 DB 스키마명 | 아래 2항 판별 순서 적용 |
| 프로시저 폴더 | 로컬 `.sql` 소스 보관 폴더 | `{PROJECT_ROOT}` 하위에서 `.sql` 프로시저 파일이 모여 있는 폴더 검색 (`05.PROCEDURE/`, `프로시저/` 등) |

- 규칙 문서의 예시 코드에 나오는 `{SCHEMA}`, `{PROJECT_ROOT}`는 그대로 쓰지 않고 항상 실제 값으로 치환하여 작성합니다.
- 다른 프로젝트의 경로(`D:\ITS_MES_...`)나 스키마명을 그대로 가져와 사용하지 않습니다.

---

### 2. `{SCHEMA}` 판별 순서
한 프로젝트 안에서도 운영/개발/사업장별로 스키마가 여러 개일 수 있으므로(예: `XXX`, `XXX_EA`, `XXX_DEV`) 프로젝트 단위가 아닌 **대상 파일 단위**로 판별합니다.
1. **기존 프로시저 수정**: 해당 `.sql` 파일 선언부(`PROCEDURE `스키마`.`프로시저명``)에 이미 적힌 스키마명을 그대로 유지합니다. 임의로 다른 스키마로 바꾸지 않습니다.
2. **신규 프로시저 작성**: 같은 업무로 함께 동작하는 프로시저(같은 화면/모듈의 `_R01`, `_S01` 등) 또는 같은 폴더·같은 접두어 파일의 스키마명을 따릅니다.
3. **판별 불가 또는 후보가 여러 개인 경우**: 임의로 정하지 않고 사용자에게 대상 스키마를 확인한 후 작성합니다.

---

### 3. 경로 표기 원칙
- `WORK_HISTORY.md`, 작업 보고 등에서 파일을 가리킬 때는 `{PROJECT_ROOT}` 기준 상대경로로 작성하고, 드라이브명·절대경로(`file:///d:/...`)를 하드코딩하지 않습니다.
- 프로젝트 폴더 구성(`01.Office`, `04.Report`, 프로시저 폴더 등)은 작업 착수 전 실제 디렉터리를 확인하여 사용합니다.
