# ITSIF_INTERFACE (IF_MONITOR) 설치 및 운영 메뉴얼

S&S INC 2공장 · ERP → MES 인터페이스 수집 프로그램 · 2026-10-27 기준

---

## 1. 무엇을 하는 프로그램인가

ERP 쪽 인터페이스 테이블(MSSQL)에 쌓인 데이터를 주기적으로 읽어서 MES 인터페이스 DB(MariaDB)의 수신 프로시저로 넘기고, 처리 결과를 ERP 쪽에 표시합니다.

```
 ERP 인터페이스 DB (MSSQL, 예: INTERFACE)          MES 인터페이스 DB (MariaDB, 예: IF_MES_SNS_FAC2)
 ┌──────────────────────────────┐                ┌──────────────────────────────────────┐
 │ FAC2_MES_ITEM  (IF_YN = N/E) │ ── ① 조회 ──▶  │ IFSTD          : 수집할 IF 목록·주기  │
 │ FAC2_MES_CUST                │                │ MES_IF_MSTITEM : 수신 프로시저        │──▶ MES_SNS2.MSTITEM 등
 │ ...                          │ ◀─ ③ Y/E 표시 ─ │ IF_ERR_LOG     : 행 단위 오류 기록    │
 └──────────────────────────────┘                └──────────────────────────────────────┘
                     ▲                                          ▲
                     └──────────── ITSIF_INTERFACE.exe ─────────┘  ② 프로시저 호출 (COMCALLC 경유)
```

1. `IF_INTERFACE` 프로시저(`RECEIVE`)로 수집 대상 IF 목록을 받는다. (`IFSTD` 에서 `IFTYPE='READ'`, `USEYN='Y'`)
2. IF 마다 주기가 지났으면 ERP 테이블에서 `IF_YN = 'N' 또는 'E'` 인 행을 최대 1000건 읽는다.
3. 읽은 행을 IF 에 등록된 수신 프로시저(`PROCNAME`)로 넘긴다. 프로시저는 MES 테이블에 반영하고, 실패한 행을 `IF_ERR_LOG` 에 기록한 뒤 그 `IFKEY` 목록을 돌려준다.
4. ERP 테이블의 처리 행은 `IF_YN = 'Y'`, 오류 행은 `IF_YN = 'E'` 로 바꾸고 `IF_READTIME` 을 기록한다. `E` 는 다음 주기에 다시 수집된다.
5. MES 프로시저 호출 자체가 실패하면 ERP 쪽 `IF_YN` 을 바꾸지 않는다. 다음 주기에 그대로 다시 수집한다.

## 2. 필요한 것

| 구분 | 내용 |
|---|---|
| PC | Windows, .NET Framework 4.0 이상 |
| MES 인터페이스 DB | MariaDB. 이 DB 에 `SETUP` 스크립트로 테이블·함수·프로시저를 만든다 |
| MES 본 DB | 수신 프로시저가 쓰는 스키마. 현재 프로시저는 **`MES_SNS2`** 스키마 테이블(MSTITEM, MSTDEPT 등)에 직접 쓴다. 같은 MariaDB 서버에 있어야 한다 |
| ERP 인터페이스 DB | MSSQL. IF 마다 `IFSTD.IFNAME` 과 같은 이름의 테이블이 있어야 한다 (4장) |
| 계정 | MES 인터페이스 DB: 프로시저 실행 + `MES_SNS2` 쓰기 권한. ERP 인터페이스 DB: IF 테이블 SELECT/UPDATE 권한 |

## 3. 배포 파일 (실행 폴더)

`bin\Release` (또는 `bin\Debug`) 폴더를 통째로 운영 PC 에 복사한다.

| 파일 | 설명 |
|---|---|
| `ITSIF_INTERFACE.exe` | 프로그램 |
| `ITSIF_INTERFACE.exe.config` | .NET 설정 (수정할 일 없음) |
| `MySql.Data.dll` | MariaDB 접속 |
| `Oracle.ManagedDataAccess.dll` | 프로젝트 참조 (현재 사용 안 함, 같이 둔다) |
| `MariaConfig.txt` | **MES 인터페이스 DB 접속정보.** 설정 화면에서 저장하면 생긴다 |
| `IfConfig.txt` | **ERP 인터페이스 DB 접속정보 · DB 종류 · 자동실행.** 설정 화면에서 저장하면 생긴다 |
| `LOG\yyyy-MM-dd\<IF명>.txt` | 실행 중 자동 생성. IF 별 OK/NG 처리 키와 오류 |
| `log.txt` | 실행 중 자동 생성. 예상 못 한 예외 |

설정 파일 형식 (직접 고칠 때 참고. 보통은 설정 화면을 쓴다):

```
MariaConfig.txt                     IfConfig.txt
--host=<주소>                       --mes_dbtype=MARIADB        (MARIADB / MYSQL)
--port=<포트>                       --erp_dbtype=MSSQL          (MSSQL / ORACLE / MARIADB)
--user=<계정>                       --erp_host=<주소>
--password=<비밀번호>               --erp_port=1433
--dbname=IF_MES_SNS_FAC2            --erp_dbname=INTERFACE      (Oracle 은 서비스명)
                                    --erp_user=<계정>
                                    --erp_password=<비밀번호>
                                    --autorun=Y                 (Y: 켜자마자 수집 시작)
```

- 두 파일이 모두 있으면 **설정 화면 없이 바로 시작**하고, `autorun=Y` 면 수집까지 바로 시작한다.
- 한 번 저장한 설정은 이 파일에 남아 다음 실행에도 그대로 쓴다. 프로그램을 새 버전으로 바꿀 때는 이 두 파일을 같이 옮긴다.
- 2026-10-27 V2 `bin\Debug` 에는 구버전과 같은 값(MES = 구버전 MariaConfig.txt, ERP = MSSQL 203.228.186.109:1433 / INTERFACE)으로 미리 넣어 두었다.

**DB 종류** — 설정 화면에서는 데이터를 보내는 쪽을 **송신 DB**(ERP), 받는 쪽을 **수신 DB**(MES)로 부른다.

| 구분 | 선택 | 비고 |
|---|---|---|
| 수신 DB (MES 인터페이스 DB) | MariaDB / MySQL | MES 쪽은 `COMCALLC` 프로시저 방식이라 MySQL 계열만 된다. 두 값 모두 같은 드라이버(MySql.Data)로 접속 |
| 송신 DB (ERP 인터페이스 DB) | MSSQL / Oracle / MariaDB·MySQL | ERP 쪽은 `SELECT ... WHERE IF_YN` / `UPDATE ... SET IF_YN` 만 쓰므로 세 종류 모두 된다. Oracle 은 DB명 칸에 **서비스명** |

> 두 파일 모두 비밀번호가 평문으로 들어 있다. 실행 폴더 접근 권한을 관리자만 갖도록 한다.

## 4. 처음 설치 순서

### 4-1. MES 인터페이스 DB (MariaDB) — `SETUP` 폴더

dbForge 등에서 **대상 DB 를 선택(`USE ...`)한 뒤** 번호 순서대로 실행한다.
현재 운영 DB(`IF_MES_SNS_FAC2`)에서 2026-10-27 에 추출한 내용이다.

| 순서 | 파일 | 내용 |
|---|---|---|
| 1 | `01_TABLES.sql` | `IFSTD`(IF 목록), `IF_ERR_LOG`(오류 로그), `COMDEBUG`(프로시저 디버그) — `IF NOT EXISTS` 라 기존 테이블은 건드리지 않음 |
| 2 | `02_FUNCTIONS.sql` | `GETPARAM`, `GETTIME`, `GETDATE`, `GETDATETIME`, `ADDDATE_MONTH` |
| 3 | `03_COMMON_PROCEDURES.sql` | `COMCALLC`(프로그램이 프로시저를 부르는 입구), `COMSPLIT`, `COMDEBUG`, `COMERR`, `IF_INTERFACE`(목록·수집대상 조회) 등 |
| 4 | `04_IF_PROCEDURES.sql` | 수신 프로시저 `MES_IF_*` 37개 |
| 5 | `05_IFSTD_DATA.sql` | `IFSTD` 등록 데이터 37건. **새로 설치할 때만** (다시 실행하면 중복 등록) |

- `03_COMMON_PROCEDURES.sql` 의 `IF_INTERFACE` 는 추출 후 RECEIVE 결과 끝에 `IFDESC` 를 더한 버전이다. 이미 설치된 DB 에는 `PATCH_20261027_IF_INTERFACE_RECEIVE_IFDESC.sql` 만 실행하면 된다. (LIST 에는 넣지 않는다 — 화면이 IFDESC 컬럼을 직접 만들기 때문에 LIST 가 돌려주면 중복 오류)
- 2~4 번은 `DROP ... IF EXISTS` 후 다시 만든다. 운영 DB 에 실행하면 **현재 프로시저를 덮어쓴다.**
- 원본의 `DEFINER` 는 빼고 추출했다. 실행한 계정이 DEFINER 가 된다.
- `MES_IF_*` 프로시저는 `MES_SNS2.<테이블>` 에 쓴다. MES 본 DB 스키마 이름이 다르면 4번 파일에서 바꿔서 실행한다.

### 4-2. ERP 인터페이스 DB (MSSQL)

IF 마다 다음 조건의 테이블이 필요하다. (ERP 쪽에서 만들어 주는 테이블)

| 조건 | 설명 |
|---|---|
| 테이블명 | `IFSTD.IFNAME` 과 같다 (예: `FAC2_MES_ITEM`) |
| **첫 번째 컬럼** | `IF_KEY` — 행 고유키. 프로그램이 첫 컬럼을 키로 써서 `WHERE IF_KEY IN (...)` 로 갱신한다 |
| `IF_YN` | `N` 신규 / `E` 오류(재수집) / `Y` 처리완료 |
| `IF_READTIME` | 프로그램이 처리 시각을 기록 |
| `IF_TYPE` | `I` 등록 / `U` 수정 / `D` 삭제 (수신 프로시저가 사용) |
| 나머지 컬럼 | 수신 프로시저 파라미터와 이름을 맞춘다 (5-3) |

### 4-3. 프로그램

1. 실행 폴더를 복사하고 `ITSIF_INTERFACE.exe` 를 실행한다.
2. 접속 설정 파일이 없으면 **설정 화면이 자동으로 뜬다.** DB 종류와 접속정보를 넣고 각각 **[연결 테스트]** → **[저장]**.
3. **'프로그램 시작 시 바로 수집 실행'** 이 체크돼 있으면(기본) 저장 다음 실행부터 켜자마자 수집을 시작한다. 끄면 메인 화면 **[▶ 실행]** 을 눌러야 시작한다.
4. PC 를 켤 때 자동으로 돌게 하려면 `ITSIF_INTERFACE.exe` 바로가기를 시작프로그램 폴더(`shell:startup`)에 넣는다.

> **구버전(`ITSIF_INTERFACE`)과 동시에 실행하지 않는다.** 둘 다 같은 ERP 행을 수집하게 된다. 신버전은 구버전을 감지하지 못하니 구버전을 먼저 종료하고 트레이 아이콘이 사라졌는지 확인한다.

## 5. 화면 설명

### 5-1. 상단

| 항목 | 설명 |
|---|---|
| **에러 로그 N건** | `IF_ERR_LOG` 전체 건수. 30초마다 확인. 0건 회색, 1건 이상 빨강. **클릭하면 최근 500건**을 오른쪽 데이터 영역에 보여준다 |
| **● 실행중 / 중지됨** | 수집 상태 |
| **[설정]** | DB 접속 설정 화면 |
| **[새로고침]** | 수집 현황 목록(IFSTD)을 다시 읽는다. 누적 건수는 유지 |
| **[▶ 실행] / [■ 중지]** | 수집 시작/중지 |

### 5-2. 수집 현황 (왼쪽)

| 컬럼 | 설명 |
|---|---|
| IF명 | `IFSTD.IFNAME` = ERP 테이블명 |
| 설명 | `IFSTD.IFDESC` (예: 품목마스터, 거래처정보). 수집 루프가 부르는 `IF_INTERFACE` RECEIVE 결과 끝 컬럼으로 받는다 — **[▶ 실행] 중에만 채워지고**, 2026-10-27 패치 반영 전 DB 에서는 빈칸 |
| 주기 | `IFSTD.CYCLE` (수시=10초, 1분, 5분, 10분, 60분, 하루) |
| 상태 | **ERP 조회중 → MES 반영중 → 완료 / 일부 오류 / 대기 / 오류** (아래) |
| 확인시각 | 마지막으로 이 IF 를 확인한 시각 |
| 처리 / 오류 | 프로그램을 켠 뒤 누적 처리건수 / 오류건수 |

| 상태 | 뜻 |
|---|---|
| ERP 조회중 | ERP 테이블에서 `IF_YN = N/E` 행을 읽는 중 |
| MES 반영중 | 수신 프로시저 실행 중 |
| 완료 | 전부 처리 |
| 일부 오류 | 일부 행이 `IF_ERR_LOG` 에 기록됨 (ERP 쪽 `IF_YN = 'E'`) |
| 대기 | 확인했지만 새 데이터 없음 |
| 오류 | 조회·프로시저·갱신 단계에서 실패. 최근 처리 이력에 사유 |

- 행을 클릭하면 오른쪽에 MES 쪽 테이블 데이터(최근 1000건)를 보여준다. (`IF_INTERFACE` 의 `VIEW_DATA`)
- 하단 상태바: `마지막 확인 시각` · `현재 수집 <IF명> · <상태>`

### 5-3. 최근 처리 이력 (오른쪽 아래)

`OK`(초록) 처리, `NG`(주황) 일부 오류, `ERR`(빨강) 실패·`IF_ERR_LOG` 신규 오류. 최근 500건만 표시.

### 5-4. 트레이

- 창 닫기(X)는 **종료가 아니라 트레이로 숨김.** 트레이 아이콘 더블클릭 또는 우클릭 → [열기].
- 종료는 트레이 우클릭 → [프로그램종료]. 실행 중이면 한 번 더 묻는다.
- 새 에러 로그가 생기면 트레이 풍선 알림이 뜬다.

## 6. 동작 상세

- **루프**: 1초마다 돈다. IF 별로 `IFSTD.LASTTIME` 기준 주기가 지났고, 프로그램이 마지막으로 확인한 뒤로도 주기가 지났을 때만 ERP 를 조회한다.
  (수신 프로시저는 데이터가 있을 때만 `LASTTIME` 을 갱신하므로, 새 데이터가 없을 때 매초 조회하지 않도록 프로그램이 따로 확인 시각을 기억한다)
- **한 번에 최대 1000건**. 남은 건 다음 주기에 이어서 처리.
- **수집 순서**: `LASTTIME` 이 오래된 IF 부터.
- **에러 로그 확인**: 실행/중지와 상관없이 30초마다 `IF_ERR_LOG` 건수를 본다. 건수가 늘면 늘어난 만큼 최근 행(최대 50)을 이력에 올리고 알림.
- **중복 실행 방지**: 같은 PC 에서 두 번 실행하면 "이미 실행중" 안내 후 종료.

## 7. IF 추가 방법

1. **ERP**: 4-2 조건으로 테이블을 만든다. 예) `FAC2_MES_XXX`
2. **MES 수신 프로시저** `MES_IF_XXX` 를 만든다. 기존 `MES_IF_MSTDEPT` 를 복사해서 고치면 된다.
   - 파라미터 이름 = **ERP 컬럼명(대문자) + `_LIST`**, 앞에 `$`. 예) ERP 컬럼 `DEPT_CD` → `IN $DEPT_CD_LIST MEDIUMTEXT`
     (프로그램이 컬럼명으로 값을 묶어 보내고 `COMCALLC` 가 이름으로 짝을 맞춘다. 이름이 다르면 빈값이 들어간다)
   - 값은 `»` 로 이어진 목록. `COMSPLIT` 으로 한 행씩 꺼낸다.
   - 행 오류는 `IF_ERR_LOG` 에 쓰고(`CONTINUE HANDLER`), 마지막에
     `UPDATE IFSTD SET LASTTIME = GETTIME() WHERE PROCNAME = '<이름>';` 와
     `SELECT IFKEY FROM IF_ERR_LOG WHERE IFKEY >= <첫키> AND IFNAME = '<이름>';` 를 반드시 넣는다. (돌려준 IFKEY 가 ERP 쪽 `E` 표시 대상)
3. **IFSTD 등록**
   ```sql
   INSERT INTO IFSTD (IFNAME, IFGB, IFTYPE, SORTNO, CYCLE, LASTTIME, PROCNAME, IFDESC, USEYN, LASTSEQ, TABLENAME, REMARK)
   VALUES ('FAC2_MES_XXX', 'ERP', 'READ', 0, '1분', '2000-01-01 00:00:00', 'MES_IF_XXX', '설명', 'Y', 0, 'MES쪽테이블', '');
   ```
   - `CYCLE` 은 `수시 / 1분 / 5분 / 10분 / 60분 / 하루` 중 하나 (그 외 값은 주기 계산 실패로 오류).
   - `TABLENAME` 은 화면에서 행 클릭 시 보여줄 MES 테이블.
4. 프로그램 **[새로고침]**. 실행 중이면 다음 루프부터 자동으로 수집된다.
5. IF 를 잠시 멈추려면 `USEYN = 'N'`.

## 8. 문제 해결

| 증상 | 확인할 것 |
|---|---|
| 시작하자마자 설정 화면이 뜬다 | `MariaConfig.txt` 또는 `IfConfig.txt` 가 실행 폴더에 없음. 설정 저장 |
| 켰는데 수집이 시작되지 않는다 | [설정] 의 '프로그램 시작 시 바로 수집 실행' 체크 확인 (`IfConfig.txt` 의 `--autorun=Y`) |
| 수집 현황이 비어 있음 | MES 접속 실패. 이력의 ERR 내용 확인 → [설정] → [연결 테스트] |
| "ERP 접속설정(IfConfig.txt)이 없습니다" | [설정] 에서 ERP 정보 저장 |
| ERP 가 Oracle 인데 조회 오류 | DB명 칸에 서비스명을 넣었는지, ERP 테이블명이 대문자 IFNAME 과 같은지 확인 |
| 특정 IF 만 계속 `오류` | 이력 내용 확인. 프로시저 없음(`PROCEDURE ... does not exist`), ERP 테이블/컬럼 불일치 등. `LOG\날짜\<IF명>.txt` 참고 |
| `일부 오류` / 에러 로그 건수 증가 | 에러 로그 배지 클릭 → `ERRMSG` 확인. 원인 해결 후 ERP 쪽 `E` 행은 다음 주기에 자동 재수집 |
| 프로시저 내부 오류 상세 | MES 인터페이스 DB `COMDEBUG` 테이블 (최근 1개월) |
| 창이 안 보임 | 트레이 아이콘 확인 (닫기 = 숨김) |

## 9. 확인이 필요한 사항 (2026-10-27 조사)

DB 는 이번 작업에서 고치지 않았다. 담당자 확인 후 처리.

1. **IFSTD 에 등록됐지만 프로시저가 없는 IF 2건** — 해당 ERP 테이블에 데이터가 들어오면 매 주기 `오류` 가 난다.
   | IFNAME | 등록된 PROCNAME | 비슷한 이름으로 DB 에 있는 프로시저 |
   |---|---|---|
   | FAC2_MES_MMP | MES_IF_MSTPRICE | MES_IF_MSTITEM_MMP |
   | FAC2_MES_BAS_STOCK | MES_IF_MSTPLAN_ITEM | MES_IF_MSTBAS_STOCK |
2. **화면의 데이터 보기 스키마** — `IF_INTERFACE` 의 `VIEW_DATA` 는 `MES_SNS.<TABLENAME>` 을 읽는데, 수신 프로시저는 `MES_SNS2` 에 쓴다. 행 클릭 시 보이는 데이터가 2공장 데이터가 아닐 수 있다.
3. **접속정보 평문 저장** — `MariaConfig.txt`, `IfConfig.txt` (구버전과 같은 방식).
