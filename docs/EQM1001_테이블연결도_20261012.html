현재 사용하는 테이블의 담당 내용과 역할

핵심 업무 테이블 9개와 조회 보조 테이블 2개를 함께 정리했습니다. 로컬 소스의 연결 기준이며 전체 DB 스키마를 의미하지 않습니다.

분류테이블담당 내용실제 역할연결 기준
기준정보COMTYPE설비그룹 코드와 명칭FM116 그룹 목록과 코드명·정렬순서를 조회한다.TPCD = MSTEQM.EQMGUBUN / G 계획의 PLANCD
기준정보MSTEQM설비와 소속 그룹사용 중인 설비를 조회하고 각 설비의 그룹을 결정한다.FANO = E 계획의 PLANCD / 실적·월계획의 EQMCD
기준정보MSTCHKKND추가할 점검항목의 원본CHKTP=02, USEYN=Y 항목을 추가 목록으로 제공한다. 추가 시 명칭·방법 등을 DETAIL에 복사한다.CHKKNDCD → DETAIL.CHKKNDCD (추가 시 복사)
계획·REVMSTEQMREV_HEADER대상별 REV와 현재 승인상태그룹·설비의 REV를 독립 관리한다. 개정내용, 요청정보, 현재 승인상태를 저장한다.PK REVCD / UNIQUE(PLANTP, PLANCD, REVNUM)
계획·REVMSTEQMREV_DETAILREV에 포함된 점검항목작업 중인 항목과 과거 승인 항목을 REV별로 저장한다. 항목 존재 여부로 포함·제외를 관리한다.PK(REVCD, CHKKNDCD) / REVCD → HEADER
처리이력CHKPLANEQM_APRV승인·반려 처리 기록 구조REV별 처리자·시간·사유를 누적한다. 현재 R03에는 승인 기록을 추가하는 실행 경로가 있다.PK APRVKEY / REVCD → HEADER (1:N)
주기관리CHKPLANEQM_YEARPLAN월별 점검자 배정R03에서 년도·설비별 월 배정을 저장한다. R04는 해당 월의 배정을 확인하여 점검을 등록한다.EQMCD → MSTEQM.FANO / YEAR + CHKTP
점검실적CHKRSTEQM실제 점검 한 건의 전체 정보설비·일자·점검자·특이사항과 당시 적용한 두 REV 키를 저장한다.PK CHKRSTKEY / REVCD·GRPREVCD → HEADER.REVCD
점검실적CHKRSTEQMKND점검항목별 결과G/E 출처별 점검값과 당시 항목정보를 저장한다. 같은 점검코드도 G와 E로 각각 보관한다.PK(CHKRSTKEY, PLANTP, CHKKNDCD) / CHKRSTKEY → 실적
조회 보조MSTEMP사원코드와 사원명요청자·승인자 명칭을 표시하고 월 배정 점검자를 사원코드로 확인한다.EMPCD ↔ REQEMP / APRVEMP / 월 배정 값
조회 보조MSTLINE라인코드와 라인명계획서 출력 시 설비가 속한 라인의 이름을 표시한다.LINECD = MSTEQM.LINECD

현재 구조를 읽는 기준

CHKPLANEQM: 기존의 설비별 현재 점검항목 목록입니다. 현재 R02~R05 정기점검 업무에서는 사용하지 않으며, 목록 역할은 REV DETAIL, 대상·버전·현재 상태는 REV HEADER가 맡습니다.

그룹과 설비: PLANTP=G/E와 PLANCD로 별도 계획을 관리합니다. 상대 대상의 REV를 생성하거나 상태를 일괄 변경하지 않습니다. R04에서 두 대상의 최신 승인 항목을 UNION ALL로 조회합니다.

승인과 항목 복사: 승인 시 DETAIL을 복사하지 않습니다. 승인본에 변경이 생겨 다음 REV를 만들 때 이전 DETAIL을 복사합니다. 승인 시에는 HEADER 상태 확정과 APRV 기록 추가를 수행합니다.

GRPREVCD: 실적이 사용한 그룹 REV의 고유키입니다. G/E는 출처, REVCD·GRPREVCD는 당시의 정확한 버전을 지정합니다. 이후 계획이 변경되어도 과거 실적의 적용 버전은 유지됩니다.

현재 소스의 기능 범위: 승인(A) 실행은 확인되었습니다. 반려 상태 표시·반려 후 재요청 로직은 있지만 현재 R03·R05에는 반려 실행 및 처리이력 팝업 호출 경로가 없습니다. 이 표는 테이블의 역할과 실제 구현 범위를 구분합니다.
